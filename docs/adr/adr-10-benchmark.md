# ADR-10: Benchmark Ground-Truth and Record/Replay Cache

**Status:** Accepted
**Date:** 2026-10-08
**Decision:** D10 — Benchmark ground-truth generation, tolerance rules, record/replay cache design.

## Context
The benchmark is a first-class deliverable with 40-50 questions across 3-5 datasets. Ground truth must be generated by scripts (never hand-typed). Results must be reproducible via record/replay of LLM responses.

## Options

### Option A: Script-Generated Ground Truth + File-Based Cache (Recommended)
Python scripts compute ground truth for each question. LLM responses cached as JSON files keyed by request hash.

| Dimension | Assessment |
|-----------|-----------|
| Complexity | Medium — scripts + cache system |
| Reproducibility | Excellent — scripts are auditable, cache is deterministic |
| Maintenance | Good — updating ground truth means updating scripts |
| Interview showcase | Strong — demonstrates rigorous evaluation methodology |

### Option B: Golden Output Files
Store expected outputs as static JSON. No generation scripts.

| Dimension | Assessment |
|-----------|-----------|
| Complexity | Low |
| Risk | High — no way to verify golden files are correct; drift over time |
| Maintenance | Poor — must manually update on data changes |

## Decision
**Option A: Script-Generated Ground Truth + File-Based Cache.**

### Ground-Truth Generation

Each benchmark question has:
```python
# benchmark/ground_truth/churn_q01.py
"""What is the overall churn rate?"""
import pandas as pd

def compute(dataset_path: str) -> dict:
    df = pd.read_csv(dataset_path)
    churn_col = "Churn"  # documented per-dataset
    rate = df[churn_col].mean()
    return {
        "question_id": "churn_q01",
        "expected_answer_type": "numeric",
        "expected_value": rate,
        "tolerance": {"type": "relative", "value": 0.01},
        "metadata": {"churn_col": churn_col, "n_rows": len(df)}
    }
```

A runner script executes all ground-truth generators and produces `benchmark/ground_truth/expected.json`.

### Tolerance Rules

| Answer Type | Tolerance | Example |
|------------|-----------|---------|
| Numeric (proportion/rate) | ±1% relative | 0.2645 ± 0.002645 |
| Numeric (count) | Exact match | 1000 = 1000 |
| Numeric (metric like RMSE) | ±5% relative | RMSE 4.23 ± 0.21 |
| Categorical (test name) | Exact string match | "Mann-Whitney U" |
| Boolean (leakage detected) | Exact match | true |
| Refusal (should refuse) | Must contain refusal indicator | `answerable: false` |
| Direction (higher/lower) | Correct direction | "higher" when A > B |

### Record/Replay Cache Design

```
benchmark/cache/
  {provider}_{model}/
    {request_hash}.json    # one file per unique LLM request
```

**Request hash:** SHA-256 of `json.dumps({"model": ..., "messages": ..., "tools": ..., "seed": ...}, sort_keys=True)`.

**Cache file format:**
```json
{
  "request_hash": "abc123...",
  "model": "llama-3.3-70b-versatile",
  "provider": "groq",
  "timestamp": "2026-10-15T...",
  "request": {"messages": [...], "tools": [...]},
  "response": {"choices": [...]},
  "usage": {"prompt_tokens": 1200, "completion_tokens": 350}
}
```

**Cache modes** (via `LLM_CACHE_MODE` env var):
| Mode | Behavior |
|------|----------|
| `off` | No caching (default for normal use) |
| `record` | Call LLM, save response to cache |
| `replay` | Use cached response only, error if not found |
| `auto` | Use cache if available, else call LLM and cache |

**CI usage:** `LLM_CACHE_MODE=replay` — tests run entirely from cache, no API calls needed.

### Benchmark Smoke Subset
- 5 questions (one per category) designated as smoke tests.
- Run in CI with cached responses.
- Full benchmark run manually or in a scheduled CI job.

### Scoring

The benchmark runner:
1. Loads questions and ground truth.
2. Runs each system (B1, A1, A2) on each question with 3 repeats.
3. Compares outputs to ground truth using tolerance rules.
4. Computes metrics: accuracy, hallucination rate, refusal accuracy, leakage detection P/R, latency, token cost.
5. Outputs: `benchmark/results/results.json` + `benchmark/results/results.md` (formatted table) + `benchmark/results/failure_analysis.md`.

## Consequences
- Ground-truth scripts are code-reviewed alongside the benchmark questions.
- Cache files should be committed to the repo (they enable reproducible CI).
- Cache invalidation: when changing model or prompt, delete cache and re-record.
- The benchmark runner is a CLI command: `python -m benchmark.runner --systems A1,A2,B1 --repeats 3`.
